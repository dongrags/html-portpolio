01 How I build software

I use AI as an engineering collaborator — not as a substitute for technical ownership.

My development workflow combines product thinking with AI-assisted implementation.

  1. 01

    Understand

    Understand the business requirement, user workflow and desired outcome.

  2. 02

    Plan

    Break the requirement into technical components, data flows, APIs and implementation tasks.

  3. 03

    Build with AI

    Use Claude, ChatGPT and Google AI Studio through VS Code to accelerate implementation and explore solutions.

  4. 04

    Review

    Inspect the generated code, architecture and behavior rather than blindly accepting AI output.

  5. 05

    Test & Debug

    Run the application, reproduce problems, investigate errors and iterate on the implementation.

  6. 06

    Deploy

    Move working changes into production and handle deployment, configuration and integration issues.

  7. 07

    Improve

    Monitor the product, add features, fix bugs and continuously improve the system.

My experience is built around shipping working software — not simply completing coding exercises.

This combination of product thinking, AI-assisted development and hands-on troubleshooting is the type of environment where I work best.

Background

Before and alongside my software work, I spent 2006 to 2025 in electronics manufacturing test, debug and failure analysis — at Jabil, from Debug Technician to Senior Test/Debug Engineer (2015–2025), and at Motorola as a Failure Analysis Technician.

That work was hardware debugging, not software — but it is where I learned structured troubleshooting: reproduce the failure, isolate the cause, fix it and keep production moving.

Why this role interests me

The Technical Operator and Web Developer role interests me because it combines several areas I have been working across in my own products: building features, fixing bugs, working with AI coding agents, reviewing AI-generated work, integrating systems and keeping production software moving.
